# 恢复和保存工作上下文

历史记录帮助找到继续的位置，当前状态决定现在能做什么。只读取本次任务需要的材料，不把恢复上下文变成重新调查所有工作。

## 恢复

用户给了完整的状态说明时先用它。否则固定主题、项目和时间窗；“最近”未指定时可用过去 7 天并说明，“全部”不能静默缩成最近几条。明确指定某个聊天时只恢复它，不先搜全历史。

优先用当前可用的记忆或聊天查询工具。只有来源不够时才读取环境明确提供的 transcript 路径，不猜其他产品的目录、不跨项目扫描。聊天工具分页到覆盖指定范围，证据不足时说明缺了哪段。

先找用户目标、决定、纠正、未完成项和产物指针，再读相关区域。记忆摘要和 agent 的完成声明只是线索；结论取决于工具具体做了什么时，回到原消息、输出或文件。

只核实会影响下一步的当前状态：分支/工作区、实际 diff、远端 PR/MR、工单、运行或发布状态。沿用领域技能访问，不因历史写着已部署就认定当前仍生效，也不恢复旧机器凭据、出口 IP 或过往生产授权。

状态清楚且验证仍覆盖相同产物时，不重复已完成的全部测试。产物变化或原证据不足时只补相关检查。需要重建历史原因再转 [why](../why/SKILL.md)，不默认全系统检索。

## 保存检查点

记录目标与范围、源码/分支/worktree、已完成和待做、决定及理由、实际验证、未验证项、下一步及证据位置。明确磁盘上有什么，不能只写“已处理”或“测试通过”。

优先更新当前任务已有的状态文件。没有指定位置时，把检查点放在仓库外的 `~/.agents/state/tasks/<task-slug>/checkpoint.md`；使用稳定的任务名，报告实际路径。记录不含密码、token、DSN 或未脱敏敏感输出。

只有长时间、多阶段或离开后需要审查取舍的任务，才按 [决策记录](references/decision-trail.md) 补充依据。普通小任务无需另建日志。

保存进度本身不包含 commit、push、stash、清理工作区或暂停仍在执行的任务。用户要求暂停时遵循已明确的暂停范围，在安全边界保存现场；有运行进程时说明其状态，不把它们默认杀掉。

## 交付

简短说明目标和当前状态、已完成/仍在做/未验证/待决定的事项、下一步，以及可打开的来源或检查点。合并、部署和验收分开表达。

待决定项只包含确实需要用户决定或提供的内容；自己还能继续做的工作不转成用户待办。来源失效或当前状态无法核实时，给出具体缺口，不补造完成状态。
