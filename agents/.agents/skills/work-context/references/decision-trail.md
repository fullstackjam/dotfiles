# 长任务的决策依据

只记会影响继续执行或复核的选择：采用/放弃方案、阶段验收、假设被推翻、回退和阻塞。不要逐条转录工具调用。

沿用任务已有的 Markdown、TSV 或其他记录，不要求统一格式。没有既有格式时，可在检查点旁用 `decisions.md` 追加记录；每条包含时间、做了什么、为什么、证据指针和结果。简短真实的句子即可。

证据指向实际文件/行、提交、MR/工单或验证产物，写入前确认能打开且支持该结论。运行记录说明目标版本、命令和观察结果，保留未验证和证据不足的状态。历史条目写错时追加更正及原因，不悄悄改成成功。

例子只表示记录方法，不是可沿用的事实：

```text
2026-11-02T10:00:00+08:00
选择：暂不删除旧配置读取路径。
理由：已确认一个消费者仍在使用，删除前需要协调升级。
证据：任务实际找到的文件行与版本，或可访问的 MR 链接。
结果：保留当前路径，消费者迁移仍未完成。
```

交付前按本次改动和输出核对新增条目及关键证据。不要因写了日志自动扩大成全 transcript 审计或跨模型 review。用户需要审查时指出真正影响判断的取舍，不强制附固定 Attention 章节。

记录默认留在本地状态目录，不自动进 Git、上传或外发。明确要求把决策依据纳入项目交付时，再按仓库规则选择跟踪位置并检查敏感信息。
